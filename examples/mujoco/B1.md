**B1 preparation: complete.** The task, 50-episode dataset recipe, frozen
evaluation suites, safety wrapper, CPU baselines/fault tests, and guarded GPU
workflow are implemented and CPU-verified.

**SmolVLA fine-tune and learned-policy study: paused—GPU required.** No base
model was downloaded, no paid infrastructure was created, and B1 itself is not
complete until a real checkpoint is trained and evaluated.

## Frozen task contract

- Instruction: `touch the red target`.
- Input: front RGB image, seven-element joint state, and camera lag. Target
  coordinates and the privileged expert goal state never enter observations.
- Output: seven finite joint targets at 20 Hz, inside actuator bounds and no
  more than the per-axis slew limit from the last safe command.
- Success: end-effector distance at or below 3 cm for five consecutive frames.
- Data: five seeded reachable goal families with initial-state and spatial
  target jitter; 40 train and 10 evaluation episodes, balanced to 10 per family,
  with at most 100 frames per episode.

The A3 joint-wave scenario remains available in `arm_dataset.py` and through
`reaching_dataset.py --scenario joint-wave`.

## CPU dataset workflow

Create the isolated environment exactly as described in
`requirements-lerobot.txt`, then run:

```bash
.venv-lerobot/bin/python examples/mujoco/reaching_dataset.py \
  --scenario red-target --split train --seed 10000 --episodes 40 \
  --output-root datasets/b1-red-target \
  --manifest datasets/b1-red-target/manifest.json

.venv-lerobot/bin/python examples/mujoco/reaching_dataset.py \
  --scenario red-target --split evaluation --seed 10000 --episodes 10 \
  --output-root datasets/b1-red-target \
  --manifest datasets/b1-red-target/manifest.json

.venv-lerobot/bin/python examples/mujoco/reaching_dataset.py \
  --manifest datasets/b1-red-target/manifest.json --validate
```

The manifest records dependency versions, git commit and dirty-worktree flag, base seeds, split,
family, initial state, target, privileged expert goal, frame count, and result.
Validation decodes every video frame and checks schema, shapes, finite values,
timestamps, actuator bounds, slew, and train/evaluation isolation. Datasets and
videos are gitignored; only compact acceptance summaries are committed.

## Policy evaluation

The evaluator accepts `oracle`, `hold`, `noise`, or `smolvla` adapters without
changing simulation code:

```bash
python examples/mujoco/evaluate_reaching.py \
  --policy-adapter oracle --suite nominal --episodes 20 --seed 70000 \
  --json-output /tmp/nominal.json

python examples/mujoco/evaluate_reaching.py \
  --policy-adapter smolvla --checkpoint /path/to/pretrained_model \
  --suite camera_shift --episodes 20 --seed 70000
```

The fixed suites are `nominal`, `camera_shift`, `lighting`, `occlusion`, and
`target_relocation`. Results include success, end-effector error, inference
latency, rejected actions, aborts, and recoveries in JSON and on a
`RESULT:<json>` line.

The wrapper validates a complete proposed action chunk before executing its
first command. Any bad shape, NaN/Inf, actuator violation, or overspeed flushes
the queue and holds the last safe command. A missing camera frame flushes and
aborts before the next MuJoCo control step.

## GPU handoff (dry-run by default)

Create a new non-ROS environment from `requirements-smolvla.txt`. Review
`training/b1_smolvla.json`; it pins `lerobot/smolvla_base`, 20,000 steps,
5,000-step saves (the frozen selection candidates are 5k/10k/20k), local
artifacts, and disabled W&B/Hub uploads.

```bash
# Validate configuration, dataset manifest, paths, and disk without training.
python scripts/b1_gpu/preflight.py

# Show commands only (all are dry-run by default).
scripts/b1_gpu/transfer.sh --host USER@GPU --remote-root /srv/robollm
scripts/b1_gpu/smoke_train.sh
scripts/b1_gpu/full_train.sh
scripts/b1_gpu/evaluate.sh --checkpoint /path/to/pretrained_model
scripts/b1_gpu/download_results.sh --host USER@GPU --remote-root /srv/robollm
scripts/b1_gpu/cleanup.sh --host USER@GPU --remote-root /srv/robollm
```

On the future GPU host, append `--execute` only after review. Execute-mode
preflight requires the full decoded dataset, LeRobot 0.6.0, a CUDA device,
30 GB free disk, a clean expected output path, and a compatible configuration.
Cleanup is recoverable: it moves the scoped remote directory into a sibling
`.robollm-trash` directory instead of deleting it.

Checkpoint suite JSON files can be ranked with:

```bash
python scripts/b1_gpu/select_checkpoint.py \
  --results-root artifacts/b1-results/by-checkpoint --execute
```

No future benchmark design decision should be needed: provision the isolated
environment, transfer the validated data, explicitly run smoke/full training,
evaluate the frozen suites, retrieve compact results, and clean up.
