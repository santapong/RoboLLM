RoboLLM's `experiment/harness-vlm-wam` baseline. Reuse its local Concept 01 model,
MuJoCo dynamics and classical inverse kinematics. Add a small text supervisor
using an NVIDIA Nemotron model through Nebius Token Factory, plus a deterministic
execution monitor. This is a proposed entry concept, not a user-confirmed final
project selection.

## Implementation findings that affect the choice

RoboLLM's `HumanoidSimulation.step()` advances MuJoCo dynamics and returns
measured hand positions. It already limits commanded joint setpoints and reports
joint-limit violations. The reported 1.1 rad/s bound applies to setpoint changes,
not a guarantee about measured physical velocity. Concept 01 has estimated
physics, fixed fingers and disabled robot self-collision. A workspace box is not
a collision certificate or a guarantee that every target is reachable. See
[the existing model notice](../../examples/humanoid_harness/MODEL_NOTICE.md) and
[Concept 01 description](../../examples/humanoid_harness/models/concept01/README.md).

POC-RobotArm's `server/services/sim.py` calls `bridge.tick()` without a
`sim.step()`. `SimBridge.tick()` also omits physics stepping. Consequently the
server motor-driven trajectory path needs correction before claiming continuous
dynamics. Jog and agent moves can still appear to work because
`src/llm/tools.py` resets joint positions directly. In particular,
`sim_move_to_xyz` applies its IK result before checking the achieved residual;
this is not a collision-checked recovery controller. Its engine is nevertheless
a useful alternative when called with an explicit physics loop and independent
validation.

## Audit execution evidence

POC-RobotArm read-only checks passed under Python 3.12.14: four catalog entries
and home-pose dimensions, normalized catalog lookup, a motion-IR JSON round-trip,
and rejection of invalid quaternions. At that audit stage pytest, PyBullet,
FastAPI and the frontend dependencies were absent, so these checks did not test
the simulator, web server or browser interface. Later installations or runs must
be documented independently.

RoboLLM contains September verification reports; those are historical artifacts,
not fresh October measurements. Record current dependency versions, exact
commands, test counts, scenario results and render artifacts after executing the
ReachGuard runner. A fixture run proves the local robotics path, not Nebius use.

## Bounded concept

The target user is a robotics learner or developer debugging a failed reach.
The task is to reach a simulated inspection point, observe that the point has
moved, and decide whether to retry from a fresh validated observation or hold.
The model receives compact simulation telemetry, not images, raw joint authority
or shell access. Deterministic code owns execution and limits.

This demo does not establish VLM, VLA or WAM inference, walking, balancing,
grasping, hardware safety, collision-free planning, or sim-to-real transfer. It
is a small simulation study of execution monitoring and bounded recovery.
